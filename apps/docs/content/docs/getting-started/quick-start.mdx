This page takes a Next.js app from nothing to its first stored event. Other stacks follow the same steps; only step 4 differs, and the [Overview](/docs#what-it-runs-on) lists what each stack uses.

## Before you start

Spoar has no sign-up form. Events go to a project, and only an admin of the API you send to can create one. That gives three roles, which can be the same person:

<Flow>
  <FlowNode label="Admin">Creates the project and hands out its keys</FlowNode>
  <FlowNode label="Developer">Puts the public key in the site and the secret key on the server</FlowNode>
  <FlowNode label="Reader">Opens the dashboard, or reads the numbers with an API token</FlowNode>
</Flow>

You need one of these:

- **Your own API.** You are the admin. [Run your own copy](/docs/guides/self-host) covers the database, the API and sign-in; step 1 below then creates the project.
- **Someone else's API.** Ask its admin for a project id, a `pk_` public key and an `sk_` secret key, and skip to step 2. Sign-in on the shared API at `api.analytics.remcostoeten.nl` is limited to allowlisted GitHub logins.

## 1. Create a project

A project is one site or app. Creating one gives you two keys:

| Key | Prefix | Where it goes |
| --- | --- | --- |
| `publicKey` | `pk_` | The browser. It is safe to ship and only works from the project's allowed origins |
| `secretKey` | `sk_` | Your server's environment. It is shown once and stored hashed, so copy it right away |

Pick the way that matches what you have:

<Tabs items={["Dashboard", "Command line", "HTTP"]}>
  <Tab value="Dashboard">
    Sign in to the dashboard at `/dashboard` with GitHub as an owner or admin, open **Projects** in the sidebar, then **New project**. Fill in the id (`example.com`), the domain and the allowed origins. The next screen shows both keys and the `.env.local` block to paste in step 3.

    Without the dashboard deployed, `<API URL>/v2/setup` on the API does the same after GitHub sign-in.
  </Tab>
  <Tab value="Command line">
    From a clone of the repository, with `DATABASE_URL` pointing at the API's database. On a fresh database, `setup` runs the migrations, allows your GitHub login and creates the first project:

    ```bash
    DATABASE_URL=postgres://... bun run setup --owner your-github-login --project example.com --domain example.com
    ```

    It prints the public and secret key. For more projects later, `bun run admin` opens a page on `127.0.0.1:3400` that writes to the same database without sign-in: it creates projects, sets allowed origins and creates `at_live_` API tokens.
  </Tab>
  <Tab value="HTTP">
    Once you have an owner session or an `admin` API token that lists no projects, `POST /v2/projects` creates one:

    ```bash
    curl -X POST https://api.example.com/v2/projects \
      -H "authorization: Bearer $RA_TOKEN" \
      -H "content-type: application/json" \
      -d '{"id":"example.com","name":"Example","domain":"example.com","allowedOrigins":["https://example.com"]}'
    ```

    The keys are in the response. This is the route for scripts and CI; your first token comes from the dashboard or `bun run admin`.
  </Tab>
</Tabs>

`POST /v2/projects/{project}/keys`, or **Rotate** in the dashboard, replaces a lost secret key.

## 2. Install the SDK

```bash
npm install @spoar/sdk
```

## 3. Configure it

Put the browser options in one environment variable, and the secret in another that never reaches the browser:

```bash
NEXT_PUBLIC_RA_CONFIG='{"project":"example.com","key":"pk_...","endpoint":"/_ra"}'
RA_SECRET=sk_...
```

Vite reads `VITE_RA_CONFIG` and Astro and SvelteKit read `PUBLIC_RA_CONFIG`, with the same JSON.

## 4. Create the client

`lib/analytics.ts`:

```ts
import { createAnalytics } from "@spoar/sdk";
import { errors, speedInsights } from "@spoar/sdk/plugins";

export const analytics = createAnalytics({
  pageviews: false,
  plugins: [speedInsights(), errors()],
});
```

`app/providers.tsx`:

```tsx
"use client";

import type { ReactNode } from "react";
import { AnalyticsProvider } from "@spoar/sdk/react";
import { Analytics } from "@spoar/sdk/next";
import { analytics } from "@/lib/analytics";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <AnalyticsProvider client={analytics}>
      <Analytics />
      {children}
    </AnalyticsProvider>
  );
}
```

`app/layout.tsx`:

```tsx
import type { ReactNode } from "react";
import { Providers } from "./providers";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

The provider lives in a Client Component because the client holds functions, which a Server Component layout cannot pass as props.

`<Analytics />` sends a pageview on every navigation with the route template, such as `/blog/[slug]`, which is why the client is created with `pageviews: false`.

Without Next.js, the client alone is enough. Import `lib/analytics.ts` once from your entry file and leave `pageviews` on: it sends a pageview on load and on every `pushState` navigation.

## 5. Serve `/_ra` from your own domain

Browsers with ad blockers drop requests to third-party analytics hosts. A same-origin path avoids that. In the App Router, `app/%5Fra/route.ts` serves `/_ra` (a folder starting with `_` is private in Next.js, so the underscore is URL-encoded):

```ts
import { createProxy } from "@spoar/sdk/proxy";

export const POST = createProxy({
  secret: process.env.RA_SECRET,
  endpoint: "https://api.example.com",
});
```

The proxy accepts only same-site `POST` requests up to 60 KB, adds the secret key, the visitor's IP and user agent, the page's origin and the admin session cookie, and forwards the body to `/v2/events`. The [proxy page](/docs/sdk/proxy) covers other runtimes.

## 6. Send an event and check it

```ts
analytics.track("signup", { plan: "pro" });
```

Open your site once with `?ra=debug` to see an `[ra]` line in the console for every event, every dropped event and every failed send. The browser remembers the setting. `analytics.status()` returns the queue size, consent, endpoint, route, last error and last send time.

In development (`NODE_ENV` is `development` or `test`) the SDK sends nothing unless an `endpoint` is set. Add `?ra=debug` to the URL to print each event to the console.

The event shows up within a few seconds on the project's **Realtime** page in the dashboard. Without the dashboard, read it with an API token:

```bash
curl https://api.example.com/v2/projects/example.com/realtime/events \
  -H "authorization: Bearer $RA_TOKEN"
```
