`@spoar/sdk/admin` is for server code, scripts and CI. It calls the API with an API token. Never ship it to a browser.

```ts
import { createAdmin } from "@spoar/sdk/admin";

const admin = createAdmin<"example.com">({
  endpoint: "https://api.example.com",
  token: process.env.SPOAR_TOKEN,
});

const week = await admin.stats("example.com", { period: "7d" });
```

It is a thin layer over [`@spoar/client`](/docs/sdk/read-client), which covers every read route. New read code should use that package directly.

## `createAdmin(options)`

```ts
createAdmin<Projects extends string = string>(options: {
  endpoint: string;
  token: string | undefined;
  fetch?: (url: string, init: RequestInit) => Promise<Response>;
  timeoutMs?: number;
}): Admin<Projects>
```

- `endpoint`: the API's base URL.
- `token`: an `at_` API token. A missing or empty token answers `NO_TOKEN` without a request.
- `fetch`: a custom `fetch`.
- `timeoutMs`: how long a request may take before it fails with `TIMEOUT`.
- `Projects`: a union of your project ids. Every method then rejects a project id outside it at compile time.

The read methods need a `read` token. Alert targets and annotation writes need an `admin` token that lists the project. [Read your data](/docs/guides/read-your-data#1-create-a-token) shows how to create one.

## Results

Every method resolves to `{ ok: true, value }` or `{ ok: false, error }` and never throws. `error.code` is a code from the [error catalog](/docs/api/overview#errors), or `NO_TOKEN`, `NETWORK`, `TIMEOUT`, `ABORTED`, `BAD_URL` or `BAD_RESPONSE` when the request did not get an answer from the API.

```ts
const result = await admin.stats("example.com");
if (!result.ok) console.error(result.error.code, result.error.message);
else console.log(result.value);
```

## Alert targets

A target is where one project's alerts go on one channel. Three builders fill one in.

### `mail(options)`

```ts
mail({ to: string[]; name?: string; on?: AlertEventName[]; enabled?: boolean })
```

`to` takes one to 20 addresses.

### `webhook(options)`

```ts
webhook({ url: string; name?: string; on?: AlertEventName[]; enabled?: boolean })
```

`url` must start with `https://`. The API signs each request. [Alert webhooks](/docs/sdk/server#alert-webhooks) shows how to verify it.

### `discord(options)`

```ts
discord({ url: string; name?: string; on?: AlertEventName[]; enabled?: boolean })
```

`url` is a Discord webhook URL.

### Defaults

- `name` defaults to the channel, so one target per channel needs no name.
- `on` defaults to every issue event, `issue.new` and `issue.regression`.
- `enabled` defaults to `true`.
- `speed.drop` is opt-in. List it in `on` to hear when yesterday's Real Experience Score fell 10 points or more, to under 90, against the 7 days before.

### `alerts.sync(project, targets)`

```ts
alerts.sync(project: Projects, targets: Target[]): Result<{
  created: string[];
  updated: string[];
  removed: string[];
  secrets: { [name: string]: string };
}>
```

Makes the project's targets match the list. It adds, updates and removes, and running it twice changes nothing. Use it to keep a project's targets in code and sync them on deploy.

```ts
import { createAdmin, discord, mail, webhook } from "@spoar/sdk/admin";

const admin = createAdmin<"example.com">({
  endpoint: "https://api.example.com",
  token: process.env.SPOAR_TOKEN,
});

const synced = await admin.alerts.sync("example.com", [
  mail({ to: ["you@example.com"] }),
  discord({ url: "https://discord.com/api/webhooks/...", on: ["issue.regression"] }),
  webhook({ name: "ops", url: "https://ops.example.com/hooks/analytics" }),
]);

if (!synced.ok) console.error(synced.error.code, synced.error.message);
else console.log(synced.value.secrets.ops);
```

`secrets` holds the signing secret of each new webhook target. It is shown only in the answer to `sync`, `set` and `rotate`. Store it where your receiver reads it, such as `SPOAR_WEBHOOK_SECRET`.

### `alerts.list(project)`

```ts
alerts.list(project: Projects): Result<AlertTarget[]>
```

Lists the targets with their `state` (`active`, `paused` or `failing`) and `stateReason`.

### `alerts.set(project, target)`

```ts
alerts.set(project: Projects, target: Target): Result<TargetChanges>
```

Creates or replaces one target.

### `alerts.remove(project, name)`

```ts
alerts.remove(project: Projects, name: string): Result<null>
```

Removes one target and its history.

### `alerts.test(project, name)`

```ts
alerts.test(project: Projects, name: string): Result<{ delivered: boolean; message: string }>
```

Sends a sample alert now. `message` is what the provider said.

### `alerts.rotate(project, name)`

```ts
alerts.rotate(project: Projects, name: string): Result<{ name: string; secret: string }>
```

Issues a new signing secret for a webhook target. The old secret stops working.

### `alerts.deliveries(project, query?)`

```ts
alerts.deliveries(
  project: Projects,
  query?: { status?: DeliveryStatus; limit?: number; cursor?: string },
): Result<AlertDeliveryList>
```

Lists the delivery history, newest first. `limit` is 1 to 100.

### `alerts.status()`

```ts
alerts.status(): Result<AlertsStatus["data"]>
```

Reports the enabled channels, the mail transport, pending deliveries and failing targets.

## Annotations

Annotations are dated labels on a project's time series, such as a release, a post, a content update or an incident. [Annotations](/docs/api/annotations) describes the data model.

Dates are a `Date`, a calendar date such as `"2026-10-01"` (the start of that day in UTC) or an ISO 8601 timestamp. `list` works with a `read` token. The other methods need an `admin` token that lists the project.

### `annotations.list(project, query?)`

```ts
annotations.list(
  project: Projects,
  query?: { period?: "24h" | "7d" | "30d" | "90d" | "12mo" | "all"; from?: AnnotationDate; to?: AnnotationDate; limit?: number; cursor?: string },
): Result<{ data: Annotation[]; nextCursor: string | null }>
```

Lists the annotations that overlap the range, oldest first.

```ts
const september = await admin.annotations.list("example.com", {
  from: "2026-09-01T00:00:00Z",
  to: "2026-10-01T00:00:00Z",
});
if (september.ok) console.table(september.value.data);
```

### `annotations.create(project, input)`

```ts
annotations.create(project: Projects, input: {
  title: string;
  date: AnnotationDate;
  endDate?: AnnotationDate;
  kind?: "release" | "post" | "content" | "incident" | "other";
  note?: string;
  url?: string;
}): Result<Annotation>
```

Adds one annotation and returns it. `url` must start with `http://` or `https://`. An `endDate` before `date` fails with `VALIDATION_FAILED` at `/endDate`.

```ts
const release = await admin.annotations.create("example.com", {
  title: "v2.0 released",
  date: new Date(),
  kind: "release",
  url: "https://example.com/changelog/v2",
});

await admin.annotations.create("example.com", {
  title: "Posted on Hacker News",
  date: "2026-10-03",
  endDate: "2026-10-05",
  kind: "post",
});
```

### `annotations.update(project, id, changes)`

```ts
annotations.update(project: Projects, id: string, changes: Partial<AnnotationInput>): Result<Annotation>
```

Changes the fields you give. `null` clears `endDate`, `note` or `url`. An empty `changes` object is a type error.

```ts
if (release.ok) {
  await admin.annotations.update("example.com", release.value.id, { note: "New onboarding flow" });
}
```

### `annotations.remove(project, id)`

```ts
annotations.remove(project: Projects, id: string): Result<null>
```

Deletes one annotation.

## Reads

The same client reads the stats routes, typed from the contract, for your own dashboard pages and server components. `filter: { country: "NL" }` is sent as `filter[country]=NL`.

```ts
type ReadOptions = {
  period?: "24h" | "7d" | "30d" | "90d" | "12mo" | "all";
  from?: string;
  to?: string;
  traffic?: "human" | "bots" | "internal" | "all";
  filter?: { [dimension: string]: string };
};
```

| Method | Route |
| --- | --- |
| `stats(project, options?)` | `GET /v2/projects/:project/stats` |
| `timeseries(project, { metric, interval?, compare?, ...ReadOptions })` | `GET /v2/projects/:project/timeseries` |
| `breakdown(project, dimension, { metrics?, limit?, cursor?, ...ReadOptions }?)` | `GET /v2/projects/:project/breakdown/:dimension` |
| `lifecycle(project, { interval?, ...ReadOptions }?)` | `GET /v2/projects/:project/lifecycle` |
| `issues(project, { status?, limit?, cursor? }?)` | `GET /v2/projects/:project/issues` |

```ts
const pages = await admin.breakdown("example.com", "page", {
  period: "7d",
  metrics: ["visitors"],
  limit: 10,
});
```

## What the editor catches

| Mistake | Caught by |
| --- | --- |
| `createAdmin<"example.com">` then `sync("exmple.com", ...)` | Type error: not a project the client was created with |
| `on: ["issue.created"]` | Type error: offers `issue.new` and `issue.regression` |
| `mail({ to: [] })` | Type error: at least one address |
| `mail({ to: ["you"] })` | Type error: `${string}@${string}.${string}` |
| `webhook({ url: "http://..." })` | Type error: `https://` only |
| Two targets with the same literal `name` | Type error on the list |
| A mail target on a deployment without `mail()` | `VALIDATION_FAILED`: "mail is not enabled on this deployment" |
| `annotations.create(project, { date: "1 October" })` | Type error: a `Date`, a calendar date or an ISO 8601 timestamp |
| `annotations.create(project, { url: "ftp://..." })` | Type error: `http://` or `https://` only |
| `annotations.create(project, { kind: "campaign" })` | Type error: `release`, `post`, `content`, `incident` or `other` |
| `annotations.update(project, id, {})` | Type error: at least one change |
| `endDate` before `date` | `VALIDATION_FAILED` at `/endDate` |
