---
title: Proxy
description: A same-origin ingest path that ad blockers do not block.
---

`createProxy` from `@spoar/sdk/proxy` returns a `(request) => Response` handler for a path on your own domain, such as `/_ra`. In the Next App Router, `app/%5Fra/route.ts` serves `/_ra`:

```ts
import { createProxy } from "@spoar/sdk/proxy";

export const POST = createProxy({
  secret: process.env.RA_SECRET,
  endpoint: "https://api.example.com",
});
```

## Options

| Option | Type | Default | Does |
| --- | --- | --- | --- |
| `secret` | `string` | `RA_CONFIG.secret` | The project's secret key (`sk_...`), from [creating a project](/docs/getting-started/quick-start#1-create-a-project) |
| `endpoint` | `string` | `RA_CONFIG.endpoint` | The API's base URL. The proxy posts to `<endpoint>/v2/events` |
| `fetch` | `(url, init) => Promise<Response>` | global `fetch` | A custom `fetch` |

Options left out are read from the JSON in `RA_CONFIG`.

## What it refuses

| Request | Answer |
| --- | --- |
| No `secret` or `endpoint` configured | `500 INTERNAL` |
| A method other than `POST` | `405 VALIDATION_FAILED` |
| A cross-site request, by `Sec-Fetch-Site` or else by `Origin` | `403 FORBIDDEN_ORIGIN` |
| A body over 60 KB | `413 PAYLOAD_TOO_LARGE` |
| The API cannot be reached | `502 UNAVAILABLE` |

Everything else is forwarded to the API with the secret key, the visitor's IP and user agent, the page's origin and the admin session cookie, and the API's answer is returned unchanged. [How it works](/docs/getting-started/how-it-works#at-the-proxy) lists each forwarded header and why.

## Page counter

`createPageCounter` counts HTML page loads in middleware as `page_request` events. Comparing them with pageviews estimates how many visitors block the client.
