The browser core has no framework dependency, so any stack that bundles ES modules can use it. Next.js and React get dedicated entries; the other stacks use the core and plugins directly.

| Stack | What you use | Page |
| --- | --- | --- |
| Next.js 15 or later | The core, `/react`, `/next`, `/proxy` and `/server` | [Next.js](/docs/frameworks/nextjs) |
| React 19 with any router, Vite | The core and `/react` | [React](/docs/frameworks/react) |
| Plain TypeScript or JavaScript with a bundler | The core and plugins | [Vanilla](/docs/frameworks/vanilla) |
| Vue with Vite or another bundler | The core and plugins | Coming soon |
| Svelte and SvelteKit | The core and plugins | Coming soon |
| Astro | The core and plugins in a client script, `/proxy` and `/server` in endpoints | Coming soon |
| Node, Bun, Deno, Vercel Functions, Cloudflare Workers, other languages | `/server` and `/proxy`, or `POST /v2/events` | [Server](/docs/frameworks/server) |

## What every setup has in common

1. A project with two keys: the public key (`pk_...`) goes to the browser, the secret key (`sk_...`) stays in server environment variables. [Quick start](/docs/getting-started/quick-start#1-create-a-project) creates both.
2. An `events.ts` type that lists your custom events once, shared by the browser and server clients. See [Concepts](/docs/getting-started/concepts#events).
3. One client created with `createAnalytics` in its own module and imported wherever you track. It starts itself only where `window` exists, so importing it during server rendering sends nothing.
4. Where you have a server, a same-origin path such as `/_ra` served by `createProxy`, so ad blockers see a first-party request. See [Proxy](/docs/sdk/proxy).
